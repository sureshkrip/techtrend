<objective>
Build the cost gate and the synchronous enrichment stage: select the top eligible items by velocity up to the hard cap, fetch grounding, cache-check on content hash, call the LLM only on a miss, and write summaries/sections (or honest tombstones) to the enrichments table — plus the standalone `python -m techtrend.enrich` entry point.

This is where the Phase 2 user story's guarantees become real: only ranking-gate survivors reach the LLM, never more than the cap, unchanged content never re-calls, and no failure ever removes a ranked row.

Purpose: the pure-ish orchestration that ties grounding + llm + cache together with per-candidate failure isolation.
Output: techtrend/pipeline/enrich.py + techtrend/enrich.py.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scores table -> gate | the eligible seam decides what reaches the (paid) LLM |
| grounding + LLM output -> enrichments table | validated model output is persisted |
| per-candidate failure -> run | one item's error must not affect the others or the ranked list |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-09 | Denial of Service | LLM spend / cost gate | high | mitigate | cap applied as SQL LIMIT to the candidate SET before any fetch (ENR-02/D-05); cache hit on content_hash skips the call (DATA-04) — bounds spend to a handful of Haiku calls/run |
| T-02-10 | Tampering | unvalidated LLM output -> SQL | medium | mitigate | enrich_item returns a Pydantic-validated EnrichmentResult; enrichments writes bind parameters, never interpolate model text into SQL (V5) |
| T-02-11 | Denial of Service | one candidate's failure aborting the run | medium | mitigate | per-candidate try/except/continue (mirrors run_collection isolation, D-10) — a dead item writes a tombstone and the run proceeds |
| T-02-12 | Spoofing | fabricated summary on empty grounding | high | mitigate | fetch_grounding None -> fetch_failed tombstone, enrich_item never called; refusal -> None -> tombstone (D-08/SC3) |
</threat_model>
