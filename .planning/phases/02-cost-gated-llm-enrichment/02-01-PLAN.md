<objective>
Lay the cost-gated-enrichment substrate: the `enrichments` cache table, the four enrichment `Tunables`, the seven-section taxonomy in config, and the Wave 0 failing tests that lock every downstream behaviour before it is built.

**As** the dashboard's daily reader, **I want** the highest-velocity items to arrive with a grounded two-line "what this is / why it matters" summary and a section I can filter by — produced within a hard LLM budget and never at the cost of losing a ranked row — **so that** I can tell in five minutes what is actually gaining traction in AI coding without reading every README myself. *(Phase 2 user story, derived from ROADMAP §Phase 2 goal + PROJECT core value.)*

This plan is the first slice of that thread: it creates the storage and config surface the enrichment stage writes to and the dashboard reads from, and writes the end-to-end failing tests (RED) that Plans 02–05 turn green.

Purpose: give every later plan a validated schema, config knobs, and a test harness — no code constants, no schema drift.
Output: extended schema.sql + config.py + tracked.toml, plus the Wave 0 test scaffolds and fixtures.
</objective>
