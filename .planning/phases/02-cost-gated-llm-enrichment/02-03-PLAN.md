<objective>
Build the grounding layer: fetch a repo's description + README intro through the existing GitHub HTTP client, extract the intro section, and normalize it for a stable content hash. This is the anti-fabrication foundation of the Phase 2 user story — summaries are grounded on freshly fetched source text, and unchanged text never re-triggers the model.

Purpose: give the enrichment stage (Plan 04) a "freshly fetched" grounding source that returns None when there is nothing real to summarize, and a normalized string whose hash is stable across badge churn.
Output: techtrend/pipeline/grounding.py.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub REST -> app | untrusted repo description + README text enters the pipeline |
| app -> content hash | normalized grounding text becomes the cache key |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Tampering | fetched README/description as untrusted input | medium | mitigate | text is treated as data; delimiter-isolation + validation happen at the LLM boundary (Plan 02) and the template boundary (Plan 05); grounding never eval's or executes fetched content |
| T-02-07 | Denial of Service | badge-churn cache defeat | medium | mitigate | normalize_for_hash strips volatile badge/comment markup before hashing so the cache actually hits for high-traffic repos, bounding LLM spend (DATA-04/D-09) |
| T-02-08 | Tampering | content-hash integrity | low | mitigate | stdlib hashlib.sha256 over utf-8 normalized text (the hashing itself lives in Plan 04); never a hand-rolled hash (V6) |
</threat_model>
