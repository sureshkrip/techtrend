<objective>
Attempt real day-one star history via sampled stargazer pagination, and — where GitHub's June/July 2026 access restriction blocks it — degrade honestly into a recorded, distinguishable state rather than silently producing an empty history.

Purpose: RESEARCH.md's Critical Finding established that the exact mechanism D-05 specifies now returns 403 for any repo the operator does not own or collaborate on, which is nearly the entire tracked set. D-08a resolved this as Option A, graceful degradation. The point of this plan is therefore NOT to make backfill work everywhere — it cannot — but to make its failure *visible and correctly classified*, so the dashboard's expected first-week sparseness reads as "still gathering data" rather than as a defect, and so a future decision on Option B is made against observed reality.

Output: Repos the operator owns get real 90-day star history; every other repo gets a `blocked` status that costs no further quota and is honestly reported.
</objective>

    The sampling algorithm is a discretion item; use a **fixed-stride reverse sample**. Compute the last page index from `stars_total` divided by the page size of 100, then request pages walking backwards from the newest with a stride chosen so the number of requests stays at or below `request_cap`. Each sampled page yields the `starred_at` of its first entry paired with the cumulative star count implied by that page's ordinal position, producing a monotonic `(date, cumulative_stars)` curve. Never walk every page — D-06's cap and the entire premise of *sampled* pagination forbid it. When the required stride would still exceed the cap, stop at the cap and return a truncated outcome carrying whatever points were gathered.

    Failure classification is the load-bearing part. Expose `classify_backfill_failure(response) -> str`. A 403 WITHOUT `x-ratelimit-remaining: 0` and any 404 are **permanent** — raise `BackfillBlocked`, and do so on the FIRST response without any retry. A 403 WITH `x-ratelimit-remaining: 0`, and any 5xx, are transient and flow through the existing `is_retryable` predicate and tenacity backoff. Conflating these two is the specific anti-pattern RESEARCH.md names: retrying a permanent platform restriction burns quota every single run on a request that can never succeed, and misrepresents the restriction as an intermittent fault. Do not decorate `sample_stargazer_history` with a blanket retry that would swallow `BackfillBlocked`.
