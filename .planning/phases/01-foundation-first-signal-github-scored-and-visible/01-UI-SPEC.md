# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Surface covered:** the single read-only dashboard route (`GET /`, `GET /?sort=…`) rendered by FastAPI + Jinja2, with htmx driving sort-as-GET-partial re-render. No other frontend surface exists in this phase (DASH-01, DASH-03, DASH-04, DASH-05, DASH-06, HEALTH-01, HEALTH-02).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-authored Jinja2 templates + one static CSS file |
| Icon library | none — plain Unicode glyphs / minimal inline SVG only |
| Font | system font stack |

**Why "none," not a gap:** `.claude/CLAUDE.md` locks this project to Python + FastAPI + Jinja2 + htmx with an explicit "no SPA, no build step" constraint, and its own What-NOT-to-Use table forbids any React/Vue/SPA toolchain. shadcn's initialization gate applies only to React/Next.js/Vite projects — this is none of those, so shadcn is correctly skipped rather than deferred. `components.json`, `tailwind.config.*`, and `package.json` were confirmed absent from the repo (greenfield, no source code yet).

- **Icons:** avoid pulling in an npm icon package (Lucide, Heroicons, etc.) purely to add a sort arrow or warning glyph — that would reintroduce the build-step dependency the stack was chosen to avoid. Use plain characters (`▲` / `▼` for active sort direction, `⚠` for the health-strip warning tier, `✕` for the failure tier) or a handful of inline `<svg>` elements committed directly into the template if a character glyph looks wrong in testing.
- **Font:** `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`. No webfont fetch — zero network dependency on page load, consistent with "local, no hosting, single user."
- **CSS:** one hand-written static file (`techtrend/web/static/style.css`), using CSS custom properties for the tokens below (`--space-md`, `--font-body`, `--color-accent`, etc.) so this contract is directly traceable into code — no CSS framework, no preprocessor.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, inline badge padding |
| sm | 8px | Table cell vertical padding, compact row spacing |
| md | 16px | Default element spacing, health-strip internal padding |
| lg | 24px | Section padding (health strip ↔ table gap, page margins on narrow viewports) |
| xl | 32px | Page-level top/bottom margin |
| 2xl | 48px | Not used in Phase 1 (single-section page has no major section breaks) |
| 3xl | 64px | Not used in Phase 1 |

**Exceptions:**
- **Table cell padding is 8px vertical / 12px horizontal** (not the 16px default) — D-14 explicitly chose a "dense sortable table" for scannability at 50+ items; the full 16px default would fight that goal. 12px is not a scale value on its own but is `sm + 4px`; treat it as a declared table-specific exception, not a new scale rung.
- **No 44px touch-target exception.** This is a locally-run, single-user desktop dashboard opened in a normal browser (D-17: started manually via `uvicorn app:app`) — there is no mobile/touch requirement in scope for Phase 1, so the usual icon-only touch-target minimum does not apply. Sort-header links and outbound links should still have a comfortable mouse hit area (≥32px row height via the `sm` vertical padding above).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 13px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

- **Body (14px/400):** table cell text — rank, repo name, velocity score, stars-gained, total stars.
- **Label (13px/600):** table column headers (sortable links), health-strip status text, footer "building history" note. Slightly smaller and bolder than body so the table reads as data-dense without looking cramped.
- **Heading (20px/600):** the single page title ("TechTrend").
- **Display (28px/600):** reserved for the health-strip's escalated warning/failure headline only (e.g. "GitHub collection failed") — the one moment in this phase the UI needs to visually interrupt a quick scan. Not used anywhere else; do not use Display for table content or it will fight the dense-table goal.

Exactly 4 sizes, exactly 2 weights (400 regular / 600 semibold) — no italics, no additional weights. This is a data-scanning tool, not an editorial layout; restraint here is deliberate.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, odd table rows |
| Secondary (30%) | `#F1F3F5` | Health-strip background (quiet/normal state), table header row background, even-row stripe, borders/dividers |
| Accent (10%) | `#2563EB` | Sortable column header link text + active-sort indicator glyph; outbound link text ("View on GitHub" / "Docs" / "Repo"); rank-number emphasis for the top 3 rows |
| Warning (semantic) | text `#92400E` on bg `#FEF3C7` | Health strip, stale-data tier (>36h since last successful run, HEALTH-02) |
| Critical (semantic) | text `#991B1B` on bg `#FEE2E2` | Health strip, hard-failure tier (collector failed, or GitHub returned zero items against a non-trivial trailing average) |

**Accent reserved for:** sort-column header links (text + active-direction glyph), the two outbound link types per row (GitHub source, docs/repo), and top-3 rank-number emphasis. Nowhere else — table body text, health-strip normal state, and page chrome stay in the dominant/secondary neutrals so the 10% stays genuinely scarce and the accent still means "you can click/act here" when it appears.

**No "Destructive" color in the traditional sense.** Phase 1's dashboard is strictly read-only (D-17 — it never triggers a pipeline run, has no delete/edit/write action of any kind), so there is no destructive-action affordance to color. The template's second-semantic-color slot is used instead for the health-strip's two escalation tiers (warning / critical) defined by D-16 — that is the only place this phase needs a second semantic meaning beyond "neutral" and "accent."

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Not applicable — read-only dashboard, no write/submit action exists in Phase 1. Nearest analog: outbound link labels, which are themselves the "action" a user takes — **"View on GitHub"** for the source link (DASH-04) and **"Docs"** / **"Repo"** for the docs-link (DASH-05, label depends on `docs_url_kind` per D-15) |
| Empty state heading | **"No data yet"** |
| Empty state body | **"No run has completed yet. Run `python -m techtrend.ingest` to collect and score your first batch."** — literal command, matching D-17's requirement that the empty state be self-explanatory rather than a blank table |
| Error state — stale (warning tier) | **"Data may be out of date — last successful run was {relative time} ago."** (e.g. "2 days ago") |
| Error state — failure (critical tier) | **"GitHub collection failed on the last run — showing data from {relative time} ago."** (e.g. "showing data from 3 days ago") when a previous successful run exists; **"GitHub collection has never completed successfully — no ranked data is available yet."** when it has not |
| Error state — DB unreadable | **"Dashboard couldn't read the database — check `techtrend.db` exists and try again."** (never a raw framework traceback) |
| Partial-history footer note | Singular: **"1 repo is still building history and isn't ranked yet."** / Plural: **"{N} repos are still building history and aren't ranked yet — check back after a few days of data collection."** — surfaces D-08a's expected first-week sparseness honestly instead of silently hiding excluded entities |
| Docs-link honesty label | **"Docs"** when `docs_url_kind` is `homepage` or `readme`; **"Repo"** when it fell back to the bare repository URL (D-15) — never labeled "Docs" when it isn't one |
| Destructive actions | **None exist in this phase.** The dashboard is pure read-only (D-17); no delete, mute, or edit affordance is in scope until later phases (muting/filtering is explicitly v2, per REQUIREMENTS.md) |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 5 covered, 4 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | ranked-table (list-collection) | ✅ covered | D-17 empty state — see Copywriting Contract "Empty state heading/body" rows |
| loading | ranked-table (list-collection) | 🧪 backstop | htmx sort GET requests dim `#table-body` to ~0.5 opacity via `hx-indicator` during the partial swap; expected sub-200ms given a local SQLite dataset of tens-to-~100 rows, so no spinner is needed — held out as backstop since actual swap latency isn't measured yet |
| error | ranked-table (list-collection) | 🧪 backstop | A DB read failure (missing/locked `techtrend.db`) renders the "Dashboard couldn't read the database" copy (see Copywriting Contract) instead of a raw 500 traceback — backstop until an actual DB-failure test exercises this path |
| populated | ranked-table (list-collection) | ✅ covered | D-14's dense sortable table: rank, name, velocity score, stars gained in window, total stars, source link, docs link — one row per entity |
| partial | ranked-table (list-collection) | ✅ covered | D-15 docs-link fallback chain (homepage → readme → repo, honestly labeled) + the partial-history footer note for entities with `window_days < 7` |
| zero-one-many | ranked-table (list-collection) | ✅ covered | Footer note branches singular/plural — see Copywriting Contract "Partial-history footer note" |
| overflow | ranked-table (list-collection) | ⚠ unresolved | No pagination or virtualization in Phase 1 — the table grows unbounded with the tracked set. Acceptable at tens-to-~100 rows for a personal single-user dashboard; treated here as a planner assumption, not a decided design, and should be revisited if the tracked set grows materially larger than that |
| error | health-strip (nav) | ✅ covered | D-16's three-tier escalation (quiet grey normal / amber stale-warning / red failure) — copy in Copywriting Contract "Error state — stale" and "Error state — failure" rows |
| overflow / long-text | health-strip (nav) | 🧪 backstop | `run_manifest.error_detail` is truncated to ~120 characters with a trailing ellipsis in the banner; the full detail is never rendered in the dashboard (stays in the log file only), avoiding a leaked stack trace onto a page that's otherwise plain-text-safe — backstop until a long-error-message case is exercised |
| long-text | ranked-table name column (interactive-control) | 🧪 backstop | `full_name` (`owner/repo`) truncates via CSS `text-overflow: ellipsis` at a fixed max-width column, with the untruncated name available via the native `title` attribute on hover — backstop until an unusually long repo name is exercised |

**Not raised (dismissed, no reason needed beyond kind mismatch):** `loading`/`empty`/`populated`/`partial`/`zero-one-many` do not apply to the health-strip (kind `nav` — those categories only apply to `form`/`list-collection`/`media` per the taxonomy); the health strip itself renders synchronously with the full page response and is never the target of an htmx partial swap, so it has no independent loading state to resolve.
