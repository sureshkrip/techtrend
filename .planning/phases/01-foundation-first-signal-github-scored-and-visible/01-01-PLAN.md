<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → process | `config/tracked.toml` and `.env` are read at startup; the TOML is hand-edited and git-tracked, the `.env` holds the only secret |
| PyPI → local environment | Eight third-party packages are installed into the venv; supply-chain integrity crosses here |
| process → filesystem | The SQLite file and the log file are written by this process |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | `pip install` of 8 core packages | high | mitigate | Task 1 blocking-human legitimacy checkpoint before first install; all 8 audited in RESEARCH.md § Package Legitimacy Audit and cross-checked against the locked `.claude/CLAUDE.md` stack |
| T-01-01 | Information Disclosure | `GITHUB_TOKEN` in `.env` | high | mitigate | `.env` added to `.gitignore` in Task 2; only `.env.example` (no value) is committed; `logging_setup` format excludes header values |
| T-01-02 | Information Disclosure | `logs/techtrend.log` | medium | mitigate | Log file gitignored; formatter records status codes and messages, never the `Authorization` header |
| T-01-03 | Tampering | `techtrend.db` written to repo root | low | accept | Single-user local tool with no remote access; the DB file is gitignored so it cannot be accidentally published |
| T-01-04 | Denial of Service | SQLite lock contention between ingest writer and dashboard reader | medium | mitigate | `PRAGMA journal_mode=WAL` + `PRAGMA busy_timeout=5000` applied in `connect()`; readers never block on the writer |
