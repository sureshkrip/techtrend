# Quick Task 260826-u0m — Raise enrichment_cap + add env override

## Why

The dashboard enriches (summarizes + classifies into a section) only the top
`enrichment_cap` items by velocity per run. With `enrichment_cap = 15`, exactly
15 items ever get a section — everything below the cap shows "summary pending"
and appears only under "All", which reads as "categorization is broken" when it
is actually the cost gate working as designed. User decision (2026-08-26):
raise the cap to 50 for better section coverage, and add a
`TECHTREND_ENRICHMENT_CAP` env override so the cap can be tuned from the Coolify
environment without a code push — mirroring the existing
`TECHTREND_ENRICHMENT_PROVIDER/_BASE_URL/_MODEL/_MAX_TOKENS/_DISABLE_THINKING`
overrides added in quick task 260822-mfu / 260822-s9h.

Config + docs + tests only. No change to enrichment logic, scoring, or schema.

## Key decisions (locked)

- New file value: `enrichment_cap = 50` in `config/tracked.toml`.
- Env override name: `TECHTREND_ENRICHMENT_CAP`, added to the existing
  `env_overrides` dict in `config.py::load_config()`. A set, non-empty value
  wins over the file value; unset/empty falls back to file → Pydantic default.
  The value arrives as a string and is coerced to `int` by
  `Config.model_validate`; the existing `gt=0` guard on `enrichment_cap`
  rejects a non-positive override loudly (same behavior as `enrichment_max_tokens`).
- While editing the `env_overrides` block, fix the stale leading comment that
  says "exactly these three enrichment fields" — it already lists five and will
  list six. Reword to "these enrichment fields" (do not enumerate a count).

## Task 1 — config value + env override

**Files:** `config/tracked.toml`, `techtrend/config.py`

- `config/tracked.toml`: change `enrichment_cap = 15` → `enrichment_cap = 50`.
- `techtrend/config.py`: in `load_config`, add
  `"enrichment_cap": os.environ.get("TECHTREND_ENRICHMENT_CAP"),` to the
  `env_overrides` dict (alongside the existing entries). Fix the stale
  "exactly these three" comment as noted above. Do NOT change the `Tunables`
  default (`Field(default=15, gt=0)`) — the tracked.toml value is the active
  setting; leaving the code default at 15 keeps the historical default honest
  and is what the file value overrides.

**Verify:** `enrichment_cap` file value is 50; `load_config()` with
`TECHTREND_ENRICHMENT_CAP` unset returns `tunables.enrichment_cap == 50`; with
`TECHTREND_ENRICHMENT_CAP=25` set returns `25` (int, not str).

**Done:** cap raised, env override wired, stale comment fixed.
